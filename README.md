# Data Centre Tycoon: 3D models

The 3D models for **Data Centre Tycoon**, a first-person PC-building and data-centre sim, and the Blender
scripts that build them. Everything here is generated by code: each model is a Python script run headless in
Blender, which exports an FBX, its textures, preview renders and an anchor report.

**The game itself is not in this repository**, only its models.

## Layout

| Path | What |
|---|---|
| `Tools/Blender/` | The build scripts. `dct_common.py` is the shared library (read its docstring first). |
| `Assets/Resources/Models/<id>.fbx` | The exported models (the game loads them from this path) |
| `Assets/Resources/Models/Textures/` | Their textures (PNG) |
| `Logs/ModelPreviews/<id>_<n>.png` | Preview renders of every model |
| `Logs/ModelPreviews/*_report.txt` | Anchor reports: every mesh with its material tag and triangles, every anchor with position, axes, size and meta |
| `docs/MODEL_PIPELINE.md` | The pipeline rules and the per-part frame and anchor contract |
| `docs/PACKAGING.md` | The packaging rig contract (boxes, cartons, inserts) and what's in each box |

The folders mirror the game's own layout, so a script finds the project root two folders above itself and writes
into the same places in the game or here.

## Building

You need **Blender 5.0.x**. Every script runs headless:

```bash
blender -b --factory-startup -P Tools/Blender/build_shipping.py -- [ids...] [--nopreview]
```

On Windows that is `"<path>\blender.exe" -b --factory-startup -P ...`.

| Script | Models |
|---|---|
| `build_parts_a.py` | Motherboards `mb_ridge_b5/z4`, I/O shields `io_ridge_b5/z4`, CPUs `cpu_arc5/arc7/tiron5`, RAM `ram_ddr5_16/ddr4_8`, SSDs `ssd_1tb/ssd_sata_500` (it calls `build_board.py`, `build_cpu.py`, `build_ram.py` and `build_ssd.py`) |
| `build_parts_b.py` | GPUs `gpu_rx66/rx88`, PSUs `psu_450/750`, coolers `cooler_stock/tower` (`build_gpu.py`, `build_psu.py`, `build_cooler.py`) |
| `build_parts_c.py` | Plugs `plug_<kind>`, screws, the brass standoff, the USB stick (`build_plugs.py`); cases `case_brickhouse/breeze` (`build_case.py`); the bench monitor `monitor_24` (`build_monitor.py`) |
| `build_boxes.py` | Retail packaging rigs `box_<partid>`, with printed art rendered from the part models |
| `build_shipping.py` | Shipping cartons and their flats, filler (paper, air pillows, bubble wrap), crumpled trash, twist ties and bags, the box cutter, unboxing table, wheelie bin, bin bags, paperwork tray |
| `build_extras.py` | Papers (`doc_*`), part caps and guards (`cap_*`, `guard_*`), the PSU voltage sticker |

### Fonts on Linux
The printed art uses Windows fonts (Arial, Segoe UI, Consolas, Impact, …). Where those aren't installed,
`dct_common.font_file` picks the closest **Liberation** or **DejaVu** font, so install them for good-looking text:

```bash
sudo apt-get install -y fonts-liberation fonts-dejavu-core
```

You can also drop font files into `Tools/Blender/fonts/` or point `DCT_FONT_DIR` at a folder.
`DCT_PROJECT` overrides the project root.

## Rules for every model
The full rules are in `docs/MODEL_PIPELINE.md`. The short version:

- **Unity coordinates.** Metres, +Y up, left-handed. Helpers take Unity coordinates; `conv()` converts to Blender.
- **Mesh names are `<name>#<tag>`**, one material per object. The tag picks the game's material:
  - plain tags such as `steel`, `black_plastic`, `pcb_green`, `cardboard`, `clear_plastic`;
  - `tex_<file>` for a textured material using `Models/Textures/<file>.png`.
  - Join by tag at the end (`c.join_by_tag`).
- **Anchors** are empties named `A_<KIND>_<NAME>_<INDEX>`, with custom props `size` (the hitbox) and `meta` (`key=value,…`).
  - Local +Z is the direction a part, plug or tool comes from. Local +Y is up.
- **Moving pieces** (flaps, lids, levers, fan rotors, caps) are separate meshes, `name@A_ANCHOR#tag`. They are modelled in the closed or installed pose, with the pivot at the anchor. The hierarchy stays flat; the game re-parents by name.
- **Look at your previews** and iterate until a model looks like the real thing at arm's length.
- **Never change a finished model's existing anchors or meshes** unless that is the task: the game depends on them. Add new models in new scripts.
  - `Tools/Blender/extras_compare.py` proves a re-export changed nothing but added anchors.
