ANCHORS (Unity metres in the part's frame; size = hitbox in the anchor's own axes; default forward +z, up +y)
  Conventions:
   - A_SOCKET_* = the seated pose of the part's origin (CPU contact face, RAM bottom-edge centre, SSD PCB
     bottom-face centre, GPU contact origin, cooler base = CPU IHS top).
   - A_PORT_* = the mouth/opening plane, forward = the side the plug comes from; meta depth=<m> is how far the
     plug face travels in when fully seated. Pin headers: anchor at the pin-tip plane; meta pin1=x,y and
     colstep/rowstep give the pin grid in the anchor's local x/y (Intel numbering: odd pins on row 0).
     Mini-Fit (24-pin, EPS): the up axis points at the latch catch (meta latch=+up).
     Rear I/O ports: forward +x, up +z (board normal). Board SATA ports: forward -x, up +z.
   - A_HOLE_n at the PCB bottom (z 0) facing -z (the standoff comes from below); A_SCREW_PH2_n at the PCB top.
   - Hinges: meta hinge=<axis>,open=<deg> in the anchor's axes; a positive angle about +x turns +y toward +z.

   2. I/O shield frame = board axes, origin at the plate centre, outer face toward +x (A_HIT_0 meta board_pose gives the pose). Place it with the same rotation as A_SOCKET_MOBO_0.
   3. A_SOCKET_PCIE16_0 kept at (0.030, -0.0427, 0.0121): slot centre y -0.045 + 2.3 mm so the GPU's fingers (GPU y -0.0023) centre in the slot; slot top z 0.0121.

   5. CPU socket kept at (0.030, 0.075); CPU seat z 0.0046, cooler pose z 0.0106.
   6. Extra anchors: A_PLATE_CPU_0 (load plate, same hinge line as the lever but opens -125 vs the lever's -115; lever meta plate=A_PLATE_CPU_0), A_KEY_M2_0 on ssd_1tb, A_HIT_0 on the shields and SSDs.
   7. DIMM slots: real 7.6 mm pitch at x -0.0304 / -0.0380 / -0.0456 / -0.0532 (A1..B2 from the CPU), centred at y 0.0673 between ATX holes J and H; latches at both ends on both boards.
   8. RAM key notch: DDR5 -0.0039, DDR4 +0.0043 from the stick centre (best estimate; DDR5 matches published measurements). A DDR5 stick turned 180 degrees has its notch 0.4 mm from the DDR4 key, so compare memory types as well, not only the notch with a loose tolerance.

dct_common ISSUES (worked around in parts_pcb; dct_common not edited)
  1. attach()/finish() do not guard Blender's 63-character object-name limit: a long '<name>@<anchor>#<tag>' is silently truncated and hashed by Blender 5, destroying the tag. parts_pcb.validate() now checks every model; keep base names short.
  2. set_parent() (used by attach) reads child.matrix_world, which is stale when a caller only set obj.location before parenting; the piece then lands at the wrong place. dct_common's own primitives are fine (set_xform assigns matrix_world). parts_pcb.Geo.obj assigns matrix_world.
  3. preview() renders Workbench MATERIAL colours, so tex_ materials show as flat grey; parts_pcb.preview() renders EEVEE with the textures bound after export (the FBX itself still carries no texture references).
  4. tube() meshes carry a UV layer from the curve conversion (harmless).
